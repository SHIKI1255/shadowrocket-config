# 独立更新健康检查

本仓库的 `.github/workflows/health.yml` 在北京时间 08:17、20:17 检查三个公开仓库，也支持手动运行。它不依赖主发布工作流是否触发，不构建或修改规则，不读取私有机场订阅，不调用 Hosts 程序，不改变 Codex 自动任务。

## 如何判定

| 对象 | 正常活动证据 | 告警条件 |
|---|---|---|
| Shadowrocket 公共生产 | main 的 validate、publish 成功，匿名下载哈希读回步骤成功 | 超过 36 小时没有成功记录 |
| QX、Clash | main 的 probe 成功；无变化时后续构建跳过仍正常 | 超过 24 小时没有成功检查记录 |
| 规则同步 | 三端固定 release 的公共包哈希、版本和消费锁定信息 | 消费者与当前公共包内容连续不同超过 24 小时 |
| 状态读取 | 工作流启用，API、清单、包哈希和历史完整可核实 | 停用或无法核实则报告需检查，不宣称已恢复 |

边界是“超过”，不是等于阈值。时间来自 GitHub 成功任务完成时间及公共 release 提交时间，统一转换 UTC 后计算；README 显示的调度时间为北京时间。PR、仅单元测试通过、失败或取消的任务不能刷新公共生产成功时间。最近历史查不到合格记录时报告“未在查询历史中找到”，不推断从未成功。

消费者定时检查为 QX 06:47/18:47、Clash 07:17/19:17。检查成功与发布成功是不同状态：无变化不要求重新发布；有变化后的构建失败仍由原发布异常 issue 立即记录，独立检查另判断持续内容滞后。公共生产主调度仍为每天 06:17。

## 防止误报与漏报

- 不使用 release 提交日期作为过期依据。规则几天不变，只要成功验证/检查仍在运行，就不报过期。
- 先固定三个 release SHA，验证公共 manifest、bundle 哈希和消费者锁定信息。shared_version 不同而 bundle_sha256 相同，记为 `metadata_pending`，不报规则滞后；正常消费者构建仍会同步版本元数据。
- 确有内容差异时回看从已消费版本到当前公共版本的线性发布历史。起点是最后一次与消费者内容相同之后的首次不同发布。后续不同版本不重置累计时间；恢复相同内容才清零。
- 活动查询最多 3 页，每页 100 个运行；发布历史最多 96 个提交。截断、非线性历史、时间异常、版本或哈希不符均记为无法核实，不将缺失证据当成零滞后。
- 通知前重读三个 release ref；采样期间发布推进则返回 `deferred_release_advanced`，不据旧证据开关告警，下次检查重新采样。

## 通知与权限

健康 issue 使用独立标记 `repository-health:v1`，只写 Shadowrocket 仓库。原来的 `release-watch:v1` 发布失败 issue 及候选 PR 机制保持独立。普通发布成功不会关闭健康告警。

只允许受信任 main 的 push、schedule、workflow_dispatch 通知；PR 只读。检查 job 只有 contents/actions read，通知 job 仅额外获得本仓库 issues write，无跨仓库写入令牌。报告绑定源提交、run_id，超过 30 分钟拒绝写入。

同一“仓库＋问题类型”不重复提交评论或刷新 issue。年龄增长、上游再次更新、版本元数据变化不会产生重复通知；问题类型改变才更新。全部检查有证据恢复正常时关闭一次。公开 API 读取失败不关闭旧告警。通知能否到达取决于 GitHub 的订阅和通知设置。

运行的 `health-report` 附件保留 7 天，记录固定发布版本、公共包哈希、最后成功时间、同步状态、错误及判定。工作流绿色仅表示检查/通知程序执行成功，是否健康以报告 `problems` 为空为准；发现问题可成功创建 issue，因此不能只看绿色。

## 验证、手动检查和回退

`python -B -m unittest discover -s tests -p test_health.py -v` 测试时间边界、无变化、元数据、连续滞后、回退、缺少证据、并发发布、可信身份及通知去重。主工作流仍运行全部测试、联网构建及离线复现，原有数量、冲突、格式和路由门槛不变。

本机只读检查：`python -B scripts/check_health.py`。如保存报告，`--output` 必须指向仓库外一个新文件。此命令不会写 GitHub issue。Actions 手动选择 `dry_run=true` 也只检查、不通知；默认运行允许按上述条件维护 issue。通知程序不批准候选 PR、不合并、不重跑发布、不回滚任何配置。

需要回退本轮功能时，通过 PR 恢复调度及健康脚本/工作流，不回退业务规则或手机配置。独立检查同样运行在 GitHub Actions：平台调度延迟、服务故障、整个仓库 Actions 被停用时无法保证及时检测，不等同于外部可用性监控。手机刷新与实际联网仍需设备验收。
