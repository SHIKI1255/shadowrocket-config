原机场节点订阅继续使用，订阅更新方式不变。Quantumult X 和 Clash 无需导入此模块。

## 安装

1. 备份手机正在使用的配置，并保存已有手动 Hosts 值；保留一个可用的备用节点。
2. 检查主配置及其他模块是否存在上述同名映射。备份后移除或停用重复记录，以免旧记录掩盖本模块是否生效。
3. 在 Shadowrocket 的模块管理中，通过上面的 Raw 地址下载模块并启用。不要把模块当作完整主配置或节点订阅导入。
4. 保持 GeekSpeed 原始订阅节点的服务器地址为域名，不改服务器 IP、端口、密码、UDP 或其他节点参数。
5. 断开并重新连接 Shadowrocket；必要时清理 DNS 缓存，按下方清单验证实际入口和访问情况。

安装 Hosts 模块不需要开启 HTTPS 解密或安装证书。主配置更新与模块更新分别管理；更新主配置后也应检查模块启用状态和同名记录是否冲突。

## 更新与维护

`GeekSpeed-Hosts.sgmodule` 是本模块唯一的生效映射文件，直接从 `main` 分发，不由每日规则生成器改写，也不放进 `release` 分支。
主配置的固定订阅地址和现有定时任务保持原样。

机场节点订阅更新、GitHub 模块修改、手机拉取模块是三个独立环节。**机场更改入口 IP，不会自动更新本模块。**
旧备份与当前订阅的三条在用入口 IP 均曾变化，不能把本次值当作永久地址。

维护步骤：

1. 在本地更新机场 Clash 订阅后，核对 `hosts` 与当前节点 `server`，确认待修改域名仍被使用。以订阅中的明确映射为依据，不用测速或普通 DNS 返回值自行挑选 IP。
2. 只修改模块中必要的映射，并同步本文的核对日期、对应表格和验证状态。不得上传原始订阅文件或包含凭据的日志。
3. 检查只有一个 `[Host]` 段、域名不重复、IP 合法，且没有增加通用设置、规则、脚本、节点或 MITM。通过 PR 审阅后合并。
4. 匿名下载固定 Raw 地址，确认新内容已可读，再在手机手动更新模块并重连、核对实际入口。若 Raw 暂未反映新提交，等待缓存刷新，不用旧内容宣称更新完成。
5. 支持模块后台更新的 Shadowrocket 版本可启用模块自动更新及 iOS 后台 App 刷新，但不保证 GitHub 修改后立即同步；首次后台刷新应单独验收。

[Shadowrocket 官方版本记录](https://apps.apple.com/us/app/shadowrocket/id932747118)列有模块自动后台更新支持。设置名称以手机版本为准。
本模块不抓取私有订阅，不自动测速选 IP，也不新增定时提交脚本。
若错误入口导致无法下载更新，先切换备用可用节点或恢复已验证的手动映射。

## 手机验收

每组测试固定网络、原始订阅节点和测试网站。每次切换模块状态后重连，必要时清理 DNS 缓存；记录的是节点实际连接的入口 IP，而非测试网站 IP 或出口 IP。

| 场景 | 验收要求 | 当前状态 |
| --- | --- | --- |
| BGP 启停对照 | 禁用失败 → 启用成功 → 禁用复现 → 启用恢复；启用后实际入口为 `27.44.143.240` | 待实机验收；手动 Hosts 有效是使用者提供的既有证据 |
| CM、CU | 分别记录启用前后入口与网页访问，启用后无回归；禁用后不要求必须失败 | 待实机验收 |
| 其他节点 | 抽查其他 GeekSpeed 节点及雪橇云，确认原有可用节点仍可用 | 待实机验收 |
| 原订阅更新 | 更新一次机场节点订阅后复测，确认原始域名节点仍受映射保护 | 待实机验收 |
| 模块更新 | 手动刷新后确认内容；后台刷新另行观察 | 待实机验收 |

若禁用后不能复现原故障，应先排除重复映射、缓存、未断开的旧连接，以及服务商已调整 DNS 或入口的情况，不为得到预期结果而故意修改节点。
源码检查、CI 和 Raw 内容核对不能替代手机解析、实际连接或后台刷新验收。

## 回退与备用方案

- 停用模块并重连可恢复原解析方式，也可能恢复原始故障。停用不是恢复网络可用性的保证。
- 恢复可用状态时，选择之前在手机验证过的模块版本，或停用模块后恢复之前验证有效的手动 BGP 映射；避免同名记录在两处同时生效。
- 在 GitHub 模块文件的历史记录中选择已验证提交，用完整提交 SHA 替换下方 `<commit-sha>`，获得不可变地址：

  ```text
  https://raw.githubusercontent.com/SHIKI1255/shadowrocket-config/<commit-sha>/modules/GeekSpeed-Hosts.sgmodule
  ```

- 首次发布没有更早的模块版本。首版固定链接只能作为后续回退基线，手机验收前不能称为已验证版本。
- 服务端回退通过新提交恢复映射内容，保留历史；手机更新滚动地址后再次验证。只在手机改动远程模块，之后更新可能覆盖该改动。
- 仅在手机确认模块没有作用于节点入口、且排除重复记录和缓存后，才使用主配置备用方案：将已核实的对应映射加入源码现有 `[Host]`，不重复创建段落，并停用模块。该方案会改变主配置，需按原仓库流程验证和发布，不在本次模块发布时预先实施。
